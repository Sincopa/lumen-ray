# Оптимизация Rust backend — 30 сентября 2026

Проверены структура Rust backend, исходные проверки и все цели Clippy.
Правки внесены в 12 Rust-файлов поверх существующих изменений рабочего дерева.
Архитектура, IPC, сериализация подписок и репозитория, приоритеты правил и возможности
Xray/Lumen Core сохранены. Зависимости не обновлялись.

## Изменения

- `services/catalog_service.rs`: индексы ID и адреса вместо повторного полного
  сканирования подписки; предыдущие узлы заимствуются без копирования credentials.
  Неоднозначные совпадения, повторные ID, порядок строк и ротация credentials
  проверяются сравнением с предыдущим алгоритмом.
- `domain/node.rs`, `xray/config.rs`, `core/lumen/routing.rs`: временный индекс
  серверов для компиляции правил с прежним приоритетом ID над ID подписки и
  выбором первого совпадения. Индексы создаются только при необходимости.
- `core/lumen/routing.rs`: поиск IP-правил только по присутствующим CIDR-префиксам,
  без выделения строки для уже нормализованных ASCII-имён. IPv4/IPv6, правило
  `/0`, доменные приоритеты и LAN bypass сравниваются с полным перебором.
- `core/lumen/outbound.rs`, `core/lumen/proxy.rs`: чтение HTTP-заголовков блоками
  вместо одного байта; сохраняются байты после `CRLFCRLF`, предел 16 KiB и
  обработка EOF. Разбор HTTP и сравнение имён заголовков требуют меньше аллокаций.
- `services/server_quality.rs`: восемь latency samples обрабатываются на стеке;
  ключи сортировки вычисляются один раз на кандидата. Медиана, штрафы и
  предпочтение выбранного сервера сохранены.
- `services/latency_service.rs`: убраны второе копирование репозитория для Lumen,
  копирование ID и промежуточный список ping endpoints.
- `subscription/parser.rs`: JSON outbounds заимствуются до необходимости
  владения ими; список строк URI не материализуется, лимит узлов сохранён.
- `storage/repository.rs`: предыдущий encrypted snapshot читается один раз;
  временные сериализованные и расшифрованные plaintext buffers обнуляются.
  Атомарное сохранение и восстановление предыдущего snapshot сохранены.
- `commands/geo.rs`: чтение и SHA-256-проверка GeoIP/GeoSite выполняются через
  `spawn_blocking`, освобождая async executor.
- `xray/updater.rs`: три компонента версии хранятся в массиве вместо `Vec`.

- После изменений: 84 Rust-теста passed, 6 ignored. Дополнительный ignored

- Проверены реальный bundled Xray через локальный SOCKS, native Lumen HTTP/SOCKS,

- `cargo build --locked --manifest-path src-tauri/Cargo.toml` прошёл: собран Windows debug executable.
- Общий `cargo fmt --check`, Prettier для проекта и `git diff --check` прошли.
- Frontend: 59 тестов, Svelte/TypeScript, ESLint и production build прошли.
- Полный браузерный E2E: **27 passed**, штатное завершение с кодом 0.

Один промежуточный параллельный Rust-прогон завершился ошибкой запуска Xray
в `bundled_xray_accepts_live_outbound_and_route_commands`. Изолированный повтор
и два следующих полных прогона прошли; причина единичного сбоя не установлена.

В первоначальном прогоне оставались ошибки общего форматирования и три E2E-сбоя.
После дополнительного запроса они исправлены:

- Rust-файлы приведены к `cargo fmt`, `src/app/App.svelte` — к Prettier.
- Браузерное демо сохраняет выбор сервера после подтверждённого переключения;
  выбор сохраняется после перезагрузки. Нативное сохранение остаётся в backend.
- Два E2E-сценария записывают скриншоты через `testInfo.outputPath()` внутри
  проекта вместо жёстко заданного внешнего пути.
- Диагностический прогон локализовал зависание на остановке тестового Vite-сервера.
  Полный повтор вне ограниченной песочницы завершился штатно: 27/27 сценариев.

После исправлений повторно прошли 84 Rust-теста (6 ignored), 59 frontend-тестов,
строгий Clippy, Windows debug build, обе проверки форматирования, Svelte/TypeScript,
ESLint, production build и полный E2E. Проверки тестов не ослаблялись.

Реальные Windows TUN, внешние приватные провайдеры и воспроизведение видео в этой
задаче не проверялись. Локальные проверки не доказывают их работоспособность.
